Step 6: Connect Servers (Trunk & DIDs)

Creates a SIP trunk between the two instances and one DID per extension, so either side can dial the other's extensions. This includes a settling wait after creation — it can take a couple of minutes.

Step 7: Connect SERVERware

Connects the SERVERware site that SwarmDialer and both PBXware instances run on, so the test script can monitor the host. All three VPSs must be on the same host. SwarmDialer turns on Observability and Collect Metrics for the PBXware VPSs.

    Runs a fixed sequence of call-load tests on remote calls (MT to CC) while monitoring the SERVERware host and the PBXware VPSs. Each test stops early if the host or a VPS is saturated. Manual dialing is paused while the script runs.

    Reset Instances

    Deletes everything SwarmDialer created on that PBXware instance — trunk, tenant & tenant package for Multi-Tenant editions, or trunk & extensions otherwise — and removes it from SwarmDialer. Does not affect anything on the other (peer) instance. Tenant deletion can take several minutes.

    Call Logs

    Deletes every saved call-batch log, both local and remote.

    Reset SwarmDialer

    Deletes SwarmDialer's saved configuration and all call logs, then restarts the GUI, back to a fresh-deployment state. Does not touch anything on PBXware — reset the instances above first if you want those cleaned up too.

    Full Reset

    Resets every connected instance, then resets SwarmDialer itself (including all call logs). This cannot be undone.
